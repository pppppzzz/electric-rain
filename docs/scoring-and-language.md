# 实时计分与中英文更新

用户最新明确规则：绿灯 +3，黄灯 -1，红灯 -1，初始 0、最低 0。此规则覆盖原始任务“只显示固件分数、保留负分”的旧要求。Arduino 的原始工程和判定逻辑保持不动，网页不计算谱面时机或正确音高，仅累计真实收到的判定结果。

## 计分来源与去重

- serial/scoring.js 集中 +3/-1/-1 算术。文本适配器每轮独立保存分数、连击与最高连击，GREEN 连击 +1，YELLOW/RED 清零。PRESS 只发声，不计分；Sonar 遥测不发声也不计分。
- 同一个非负 event 索引的 GREEN/RED 只认首个最终判定，重复行不再次加扣分。YELLOW 的 event 始终为 -1，按同一真实 PRESS 最多扣一次；下一个 PRESS 的真实黄灯仍扣一次。
- 黄灯没有目标编号，不能可靠判断后续哪条 RED 对应之前哪次黄灯。因此当前按实际灯色事件分别计分：真实黄灯一次 -1，后续新的有效 RED 再 -1。未猜测谱面关联。若将来要求同一目标黄→红只扣一次，需要固件增加关联编号。
- JSON 显式 score 保持权威，不再加命中奖励，并按最新最低分规则截到 0。模拟模式单独使用相同规则，不能与硬件事件混入同一轮。
- Song finished 锁定最终成绩；后续自动校准不会清空正在展示的结算。Return/10 秒返回或新歌重新开始时归零。刷新、断开后重连按新会话处理，不将不完整记录冒充连续整轮。
- 完整模拟的固定事件序列为 10 次命中、1 次提前、1 次漏音：最终 28 分，最高连击 6；这些明确属于模拟数据。

## 双语

默认中文；右上角 English / 中文 切换全部主流程、曲名、控制台、提示和常见串口错误。语言存在浏览器 localStorage，文件页面存储被拒绝也能正常切换。切换只刷新文本，不重置分数、连击、唱片动画计时、音频或串口。原始串口内容和开发日志保留原文便于核对。

# UNO R3 交互钢琴：交通灯反馈版

打开 `InteractivePiano.ino`，把 Config.h、Songs.h、GameRules.h 保留在同一文件夹。开发板选择 Arduino Uno，选择对应 COM 端口后重新上传。串口监视器设置 115200 波特率。程序不再控制蜂鸣器，请拆下蜂鸣器接线。

## 交通灯接线

这里使用数字 GPIO 控制，**不是串口 TX/RX 接线**。默认针对带限流电阻、5V UNO 兼容的四脚 GND/R/Y/G 交通灯模块。先断电，按模块丝印接线：

| 交通灯模块端子 | UNO R3 |
|---|---|
| R / 红灯 | D3 |
| Y / 黄灯 | D4 |
| G / 绿灯 | D5 |
| GND / − | GND |

注意 G（绿色）与 GND（地）不能混淆。四脚模块通常没有独立 VCC，不要把绿灯 G 接成地。如果模块另外带 VCC，且标注支持 5V，则 VCC 接 5V、GND 接地，R/Y/G 仍按表连接；若端子只有 VCC/GND/DIN，或为大功率交通灯，请先确认型号，不能套用此接法。裸 LED 每一路必须配限流电阻，不能直接接 GPIO。

默认 HIGH 亮灯。若模块说明明确标注低电平有效，修改 Config.h 的 `LED_ON=LOW`。所有模块共地。D9 已不再使用，D0/D1 保留给 USB 串口。

上传后在串口发送小写字母 `l`（不是数字 1）：依次红、黄、绿，各亮 1 秒。若颜色顺序不对，核对 R/Y/G 接线；若不亮，核对模块型号、电平、地线和限流电路。

## 其他模块接线保持原样

| 模块信号 | UNO R3 |
|---|---|
| 声音 AO | A0 |
| 超声波 Trig / Echo | D6 / D7 |
| 点阵 IN 端 DIN / CLK / CS | D11 / D13 / D10 |
| 声音、超声波 VCC / GND | 5V / GND |
| 点阵 VCC / GND | 按原供电接法，5V / 共地 |

点阵映射、方向、四列一键、4×2 方块和原下落动画保持不变。四联点阵保持低亮度；独立 5V 电源供点阵时与 UNO 共地，避免与 USB 的 5V 电源直接并联。

## 游戏流程与选曲

1. 启动后安静 2 秒，中央闪烁时开始吹气。
2. 连续三个 20 ms 窗口达到 350 后开始采集，继续采集约 1.2 秒，取窗口峰峰值的最大值选歌。
3. 显示 1/2/3 个方块确认曲目，然后开始游戏。选曲后直到本轮结束，不再读取声音传感器。
4. 每轮结束后等待 1.5 秒，再进行 2 秒环境采样，中央闪烁后可再次吹气。可重复游玩。

| 声音强度（含端点） | 结果 |
|---|---|
| 0–549 | 低于选曲范围；若已触发采样则提示用力一点重试，不进入游戏 |
| 550–600 | 茉莉花 |
| 601–650 | 铃儿响叮当 |
| 651–700 | 洋娃娃和小熊跳舞 |
| 701–1023 | 超出指定范围，提示轻一点重新吹气，不进入游戏 |

**数值定义：** 20 ms 内 A0 最大读数减最小读数，范围 0–1023，是 ADC 峰峰值，不是分贝，也不是单次 analogRead 的直流电平。本版不再减去底噪。启动时的环境采样仅打印参考底噪，不改变选曲门限。串口 `Blow strength` 是当前窗口值，`Captured peak` 是最终选歌值。

**选曲分档与启动门限分开：** 上表是采样后的分类规则；选曲前仍保留 `BLOW_TRIGGER=350`、连续三个窗口确认吹气的启动条件。因此单独的 0–349 读数不会启动采样；触发采样后，只有最终峰值在 550–700 内才选歌。最终峰值低于 550 或超过 700，都会提示重新吹气，不默认归入低档或高档。

## 按键与红黄绿判定（不计分）

只反馈灯色，不记录分数、不加分或扣分。

| 情况 | 灯色 |
|---|---|
| 对应方块在最底两行时，检测到对应琴键的新按下 | 绿 |
| 方块还未到底就按对应键，或按错键 | 黄 |
| 方块到底并超过判定时间，仍未按中 | 红 |

保留原点阵动画：方块出现后约 1200 ms 到最底两行，1580 ms 消失。v3.2 使用**适度容错**：

- 绿灯仍要求选中正确琴键，默认命中窗口为出现后的 1200–1780 ms（在原窗口后追加 200 ms）。
- 在到底前 130 ms 内检测到一个新的正确按下，可短暂缓冲；先亮黄灯提示，保持这个位置，到底时转为绿灯。
- 更早的按下不缓存。一直把手停在某个位置，不能自动命中后面的音符。连续同音仍须移开再进入。
- 提前或按错仅亮黄灯提醒，不会把音符永久判错；可以在窗口内重新按对。超过窗口仍未按中，才亮红灯。
- 每个音符只命中一次。空白时乱按会亮黄灯，但不影响之后的音符。

**距离稳定性：** 每 65 ms 测量一次，连续两次一致才确认换键。已确认的琴键在内部边界外 3 mm 范围内保留原键，减少小幅抖动跳键；3 cm 和 15 cm 的总范围不向外扩张。换键请移到区域中心，不能仅贴着边界移动。超界或无回波连续两次才确认松开，单次异常不会制造新按键。早按缓冲要求当前仍有新鲜、稳定回波；无回波或移开会取消缓冲。

重新按同一个音：手先移出 3–15 cm 范围约 130 ms，再进入该键中心。不会因长期停留而自动命中下一音符。串口的 `target key` 是原始距离分区，`stable key` 是已确认琴键（0 表示未确认或松开），两者在边界防抖时可以短暂不同。

**现场排查：** 先发送 `l` 检查绿灯能否独立亮起，再发送 `t`，固定一块平整硬纸板或手掌在例如 8.25 cm 处，观察 stable key 能否保持 4。探头正对反射面，避免只用指尖或让桌面、杜邦线成为主要反射物。若静止时读数仍跨多个琴键跳动，先处理摆放、反射面与供电；软件的 3 mm 防抖无法消除大幅错误回波。

HC-SR04 文档给出的测量角约 15°，建议测量周期大于 60 ms。因此每键仅 1.5 cm 的设计仍需要现场定位，不能把它当作精确的实体按键开关。[模块资料](https://www.elecfreaks.com/download/HC-SR04.pdf)

单个超声波测的是手的前后距离，不是实体按键开关，也不能检测和弦。

| 琴键 | 距离 d（厘米） | 中心位置（厘米） |
|---|---|---|
| 1 | 3 ≤ d < 4.5 | 3.75 |
| 2 | 4.5 ≤ d < 6 | 5.25 |
| 3 | 6 ≤ d < 7.5 | 6.75 |
| 4 | 7.5 ≤ d < 9 | 8.25 |
| 5 | 9 ≤ d < 10.5 | 9.75 |
| 6 | 10.5 ≤ d < 12 | 11.25 |
| 7 | 12 ≤ d < 13.5 | 12.75 |
| 8 | 13.5 ≤ d < 15 | 14.25 |

## 曲谱、空拍与速度

Songs.h 保持图片中所有数字及原有空格。一个数字占一拍，一个原有空格休止一拍，**每个换行空两拍**（在每行末尾额外写两个空格；最后一行不附加换行）。每拍默认 500 ms，可修改 Config.h 的 SCORE_BEAT_MS。

茉莉花：40 个音符、16 空拍，共 56 拍。铃儿响叮当：44 个音符、14 空拍，共 58 拍。洋娃娃和小熊跳舞：70 个音符、46 空拍，共 116 拍。空拍没有提示块，也不会因无人按键而亮红灯。

## 调试命令与日志

| 串口命令 | 功能 |
|---|---|
| l | 红黄绿灯依次测试，然后恢复等待选歌 |
| t | 保留原点阵方向测试；每个新的有效距离按键闪绿灯，不计分 |
| 1 / 2 / 3 | 直接选择对应歌曲，便于测试判定 |
| r | 终止当前轮，重新等待吹气 |

`PRESS mm=... key=...` 表示检测到新按下；`GREEN HIT`、`YELLOW EARLY/WRONG`、`RED MISS` 表示本次灯光判定，event 是曲谱位置索引。结束时打印 `Song finished`，不统计分数。

`NO ECHO` 表示未测到回波，检查 Trig=D6、Echo=D7、电源、地线、反射面；`OUTSIDE 30..149 mm` 表示手不在琴键范围内。选歌和游戏判定阶段不能同时运行。

## 验证

### 点阵全部常亮的诊断（v3.1）

整块 32×8 全亮不是游戏的正常画面。MAX7219 的全亮测试模式会覆盖像素数据；通信接触不良、供电异常或控制状态错误都需要检查，不能只凭照片确认原因。

v3.1 保留方向、图案和游戏规则，增加点阵恢复功能：SPI 时钟从 1 MHz 降至 250 kHz；上电关闭全亮测试并清屏；每秒重写一次正常显示配置，不清除正在运行的动画。此措施不能修复断线、供电不足或损坏的模块。

重新上传后，在 115200 波特率串口依次测试：

1. 发送 `x`，应看到 `BLANK commands sent`，点阵全部熄灭并保持清屏状态。此模式暂停游戏、超声波和声音检测。
2. 发送 `m`（或 `t`），应看到 `MATRIX commands sent`，出现单个下落方块测试。
3. 测试正常后发送 `r` 恢复吹气选歌，或发送 `1` 直接开始茉莉花。

如果串口确认收到 `x`，但点阵仍全部亮着，说明这组清屏命令未在模块上生效。先完全断开 USB 和点阵独立电源，按实际丝印检查 IN 端 DIN→D11、CLK→D13、CS/LOAD→D10、GND→共地以及稳定 5V 供电；检查是否有松动、插错面包板行、信号线短接。重新上电后再试。交通灯与超声波正常不代表点阵的三根通信线正常。

MAX7219 此接法没有状态读回，串口的 commands sent 只表示程序发出了命令，不能证明点阵已收到。必要时换短杜邦线，或将点阵单独连接 UNO 验证。不要带电插拔。

资料：[MAX7219/MAX7221 厂商手册，第 10 页 Display-Test Register](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX7219-MAX7221.pdf)。

verify-build.ps1 使用本机 Arduino AVR 工具链编译和链接，不上传开发板。GameRules.h 含选曲端点、距离端点以及命中/漏按时间边界的编译期检查。程序尚需实物测试交通灯极性、超声波响应和吹气阈值。

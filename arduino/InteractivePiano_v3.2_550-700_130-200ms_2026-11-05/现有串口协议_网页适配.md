# 现有串口输出适配说明（源码核对，不是实测日志）

115200 波特率、8数据位、无校验、1停止位、无硬件流控。Arduino println 输出 CRLF；所有输出是ASCII文本。接收数据可能分块或一块含多行，网页需持续拼接缓冲后按换行解析。不要假定一次读取就是一行。打开串口可能让UNO复位并从校准开始。

## 正常生命周期

1. 启动横幅：`Interactive Piano v3.2 MODERATE | r: restart | 1/2/3: song | t/m: reset matrix + animation | x: blank matrix | l: LED test`
2. `Keep quiet for 2 seconds: calibrating microphone.`：开始环境采样。
3. `Noise floor=<整数>`：参考底噪；不用于扣减选曲强度。
4. `Blow now: soft / medium / strong.`：开始等待吹气。
5. `Blow strength=<整数>`：约每250ms输出当前20ms窗口峰峰值；并不是分贝。
6. `Captured peak=<整数>`：本次吹气测量完成。有效范围内随后输出选曲，范围外提示重试。
7. `Selected: Mo Li Hua` 或 `Selected: Jingle Bells` 或 `Selected: Doll and Bear Dance`。
8. `Microphone locked. Play when blocks reach the bottom. r = restart.`：进入选曲后的倒计时，不等于游戏计时已经开始。
9. 倒计时约1500ms后内部转为PLAYING，但**没有专门的开始消息**。超声波/判定输出随后出现。
10. `Song finished. Quiet pause, then recalibrate and blow again.`：本轮结束。
11. 约1500ms后再次输出步骤2；校准约2000ms后再次输出步骤3、4。

网页可暂把 Selected 识别为“已选歌/准备”，把锁定消息后约1500ms标为“推测开始”；这不是板端确认接口。第一条超声波消息也不是可靠的精确开始时间，测试模式同样会输出距离。不要擅自当作已存在 START、READY、SCORE 或 JSON 协议。

## 选曲失败（完整原文模板）

- `Below 550: no song selected. Blow harder and try again.`
- `Above 700: no song selected. Blow more gently and try again.`

这两种情况直接回到等待吹气，不重新发出 Blow now 消息；网页需据此重置选曲状态。串口命令1/2/3会绕过吹气，可能没有 Captured peak。

## 演奏输出（完整原文模板）

- `Sonar: NO ECHO. Check Trig=D6, Echo=D7, 5V, GND.`
- `Sonar raw mm=<毫米> OUTSIDE 30..149 mm -> released`
- `Sonar raw mm=<毫米> target key=<1..8> stable key=<0..8>`
- `PRESS mm=<毫米> key=<1..8>`
- `GREEN HIT event=<非负整数>`
- `YELLOW EARLY/WRONG event=-1`
- `RED MISS event=<非负整数>`

距离诊断约500ms输出一次。stable key=0 表示未确认/松开；日志打印发生在本次采样确认前，可能比本次测量落后一步。PRESS 是连续两次确认后的新按键；早按缓冲可能稍后才输出GREEN，不一定紧跟PRESS。

event 是 Songs.h 拼接字符串的**0起始字符索引**，包含空拍位置，并非音符序号。每个字符500ms，行间用两个空格表示两拍。游戏生成目标由字符串数字决定。三首曲子分别有56/58/116个字符、40/44/70个音符。

GREEN、RED会终结对应音符，每音符最多一种最终结果。YELLOW event=-1只是提醒，不终结音符，可能重复，也可能随后对同一个音符GREEN。没有稳定的序号或消息重放机制，因此仅靠文本不能跨断线保证统计无重复/无遗漏。

## 当前没有成绩接口

固件不保存或输出score、最终成绩、命中率、开始时间戳、局号。结束仅有上面的Song finished句子。网页如需临时统计，可在新局清空缓存，对GREEN/RED按event去重，YELLOW单独计提醒次数；这些只能标为“网页统计”，不能当板端成绩，也不能把YELLOW直接当最终失败。正式开始状态和成绩接口留待共同确认，本包不新增。

## 电脑可发送的现有命令

`r`：重新校准；`1/2/3`：直接选歌；`l`：交通灯测试；`t/m`：点阵恢复+动画及超声波测试；`x`：持续清屏。大小写字母均可。换行符被忽略。调试命令中断当前游戏，但不发送Song finished；网页若主动发送命令，应同步更新自己的状态。

调试文本：
- `LED TEST: red, yellow, green; 1 second each.`
- `MATRIX commands sent (no readback). Expect falling blocks. Sonar press flashes green. x: blank, r: game.`
- `BLANK commands sent. All pixels should be OFF. If still all ON, check IN/DIN=D11/CLK=D13/CS=D10/GND/power. m: animation, r: game.`

测试模式绿灯并不输出GREEN HIT；不要把测试按键当正式演奏。最终请用真实完整日志复核本说明中的文本解析和顺序。
